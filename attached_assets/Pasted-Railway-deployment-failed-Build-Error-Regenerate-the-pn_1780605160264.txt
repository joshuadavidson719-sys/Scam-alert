## Problem
The @workspace/api-server service (RAILPACK builder) fails at the BUILD stage. The build runs `pnpm install --frozen-lockfile --prefer-offline` which exits with:

```
ERR_PNPM_LOCKFILE_CONFIG_MISMATCH  Cannot proceed with the frozen installation. The current "overrides" configuration doesn't match the value found in the lockfile
```

SNAPSHOT_CODE completed successfully. No config file (railway.json/railway.toml) is present — all settings come from the dashboard. The start command is `pnpm --filter @workspace/api-server start`.

## Diagnosis
The pnpm-workspace.yaml file contains an overrides section with 80+ entries that exclude platform-specific optional dependencies for esbuild, lightningcss, tailwindcss/oxide, rollup, and expo/ngrok-bin, plus an esbuild version pin and a tsx override. These overrides were modified without regenerating pnpm-lock.yaml. When pnpm runs with --frozen-lockfile, it compares the current workspace config against the lockfile and rejects the mismatch. The triggering commit only added a screenshot image — this mismatch existed before this deployment.

## Fix
1. **File:** `pnpm-lock.yaml` (repo root)
2. **Current state:** The lockfile's recorded overrides do not match the overrides section in pnpm-workspace.yaml
3. **Required action:** Run `pnpm install --no-frozen-lockfile` locally in the repo root to regenerate pnpm-lock.yaml, then commit and push the updated file
4. **Why this fixes it:** The regenerated lockfile will include the current overrides configuration, allowing `pnpm install --frozen-lockfile` to succeed during the Railway build
