## Problem
This is a pnpm workspace monorepo (13 projects) using the RAILPACK builder. The build fails at the dependency install step with:
```
ERR_PNPM_LOCKFILE_CONFIG_MISMATCH  Cannot proceed with the frozen installation. The current "overrides" configuration doesn't match the value found in the lockfile
```
SNAPSHOT_CODE succeeded. BUILD_IMAGE failed. The start command (`pnpm --filter @workspace/api-server start`) is set via the dashboard. No config file is in use.

## Diagnosis
The `pnpm-workspace.yaml` file contains an `overrides` section that excludes non-linux-x64 platform-specific packages (for esbuild, lightningcss, @tailwindcss/oxide, rollup, @expo/ngrok-bin) and overrides the esbuild version to `0.27.3`. These overrides were added or modified after the last time `pnpm-lock.yaml` was generated. When Railway runs `pnpm install --frozen-lockfile`, pnpm detects that the overrides in the workspace config do not match what is recorded in the lockfile and refuses to proceed. The triggering commit only added `push.sh` and made no changes to any dependency or workspace config files, confirming this is a pre-existing mismatch that has caused at least 4 consecutive deployment failures.

## Fix
1. Open a terminal in the project root (locally or in the Replit shell).
2. Run: `pnpm install --no-frozen-lockfile`
3. This regenerates `pnpm-lock.yaml` to reflect the current `overrides` configuration in `pnpm-workspace.yaml`.
4. Commit and push the updated lockfile:
```
git add pnpm-lock.yaml
git commit -m "Regenerate lockfile to match workspace overrides"
git push origin main
```
This resolves the issue because the lockfile will then match the overrides configuration, and `pnpm install --frozen-lockfile` will succeed on the next Railway build.
