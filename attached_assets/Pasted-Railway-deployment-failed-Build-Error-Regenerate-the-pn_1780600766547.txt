## Problem
The @workspace/api-server service fails during the BUILD stage when pnpm runs `pnpm install --frozen-lockfile --prefer-offline`. The error is:

```
ERR_PNPM_LOCKFILE_CONFIG_MISMATCH  Cannot proceed with the frozen installation. The current "overrides" configuration doesn't match the value found in the lockfile
Update your lockfile using "pnpm install --no-frozen-lockfile"
```

The SNAPSHOT stage completed successfully. The BUILD stage failed at the dependency install step. The build command is configured as `pnpm --filter @workspace/api-server build` (set in the Railway dashboard), but the failure occurs before that command runs.

## Diagnosis
The pnpm-workspace.yaml file contains an `overrides` section with platform-specific package exclusions (esbuild, lightningcss, @tailwindcss/oxide, rollup, @expo/ngrok-bin) and version overrides (`esbuild: "0.27.3"`, `@esbuild-kit/esm-loader: "npm:tsx@^4.21.0"`). These overrides were modified after pnpm-lock.yaml was last generated, creating a mismatch. Railway's build runs `pnpm install --frozen-lockfile`, which correctly refuses to proceed when the lockfile does not reflect the current configuration. The triggering commit only added a PNG file and did not cause this issue — the mismatch pre-existed.

## Fix
This fix requires running a command locally and cannot be implemented by editing files alone:

1. Clone the repository and checkout the `main` branch.
2. Run `pnpm install --no-frozen-lockfile` to regenerate pnpm-lock.yaml with the current overrides from pnpm-workspace.yaml.
3. Commit and push the updated `pnpm-lock.yaml`.

The updated lockfile will include the overrides from pnpm-workspace.yaml, resolving the ERR_PNPM_LOCKFILE_CONFIG_MISMATCH error on the next deployment.
